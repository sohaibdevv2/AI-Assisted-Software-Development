03 / Use the surface well

Four different instincts.

01 / VS CODE

Compose your workbench.

Use it when debugging, remote development, extension choice, and team control matter more than a single AI experience.

02 / CURSOR

Talk to the codebase.

Start with repository questions, ask for a plan, then keep edits narrow and inspect every generated diff.

03 / ANTIGRAVITY

Test the agent boundary.

Benchmark it on a real bug, a multi-file feature, and a rejected command before making it a team default.

04 / CODEX

Delegate a contract.

Give the task a goal, repository facts, constraints, acceptance criteria, and a verification command.

06 / The loop

Make verification part of the prompt.

01

Define the outcome

Write inputs, outputs, constraints, failure behavior, and non-goals.

02

Establish context

Give the tool the relevant files, runtime, conventions, and existing tests.

03

Request a plan

Ask for the owning path, proposed files, risks, and validation commands.

04

Implement in slices

Prefer a vertical slice that can be tested over a large rewrite.

05

Verify independently

Run tests, type checks, lint, builds, and security scans where needed.

06

Review what tests miss

Check authorization, data exposure, performance, compatibility, and accessibility.

Human checkpoint: require approval before package changes, destructive commands, infrastructure work, secret access, migrations, billing, or permission changes.
07 / Stay current

Track the curve, not the hype.

Keep a small evaluation harness and re-run it when a new editor, model, or extension claims to change your workflow.

Follow primary sources.

Read official release notes, model docs, pricing, retention policies, and security advisories first.

Keep 10–20 real tasks.

Use representative bugs, features, refactors, security reviews, UI tasks, and legacy-code questions.

Measure verified delivery.

Track correctness, review effort, total cycle time, cost, retries, and reopened bugs.

Keep a rollback path.

Document alternatives, pin where sensible, and keep repository commands independent of one assistant.

The durable advantage
Precise context, capable models, clear boundaries, and evidence.
